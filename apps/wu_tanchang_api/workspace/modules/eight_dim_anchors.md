# MODULE:eight_dim_anchors — 八维锚点（初步建议）

本模块开启时执行。关闭时整段跳过：材料里不要写二、三节，聊天里不要列举八维。

## 定位

七维是**画像**。八维是吴探长或其团队**见面时深挖、最终方案往上钉**的锚点。

本模块产出的是给**用户也能看见**的面谈前初步框架，让用户对即将发生的见面有实质期待和准备。  
**不是最终方案，不是到店诊断，不打 0–10 分，聊天收集阶段不要念「你是第 X 维」。**

## 八个锚点

**战略层（做对的事）**

1. 行业赛道与品类战略 — 这个品类还能不能做
2. 市场细分与目标客群定位 — 客群是谁、在哪
3. 业务设计与菜单工程 — 菜单在赚钱还是漏钱
4. 品牌叙事与价值传递 — 顾客凭什么记住你

**执行层（把事做对）**

5. 全触点体验与峰值设计 — 离店后还能想起什么
6. 空间场景与高效动线 — 空间在帮赚钱还是帮亏钱
7. 运营系统与服务标准 — 人走了店还能不能转

**迭代层（持续赚钱）**

8. 投资测算与模型迭代 — 到底能不能赚钱、多久回本

## 怎么挂（强制）

- 只挂 **1–3 个**有证据的锚点，证据必须能回指画像里的用户原话
- 没证据的维不要凑满八条
- 每个锚点写清：为何挂在这里、见面建议用户准备什么（菜单/客单区间/铺位类型/平面或动线照片/账目口径等，按阶段取用）

## 材料落点（给用户和吴探长看同一份）

- **二、初步建议（八维锚点）**：3–6 句收束，点名将展开的锚点；说明「见面会从这里开始，结论见面后由吴探长团队给出」
- **三、建议讨论话题**：每条对应一个已挂锚点，便于见面按议程展开

## 边界

- 禁止把锚点写成已经诊断完的结论
- 禁止预算拆解和可执行 SOP（那是见面之后人的团队交付，仍映射回这八个锚点）
