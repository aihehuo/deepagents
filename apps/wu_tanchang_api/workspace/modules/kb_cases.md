# MODULE:kb_cases — 可参考案例

本模块开启时执行。关闭时**禁止**调用 `kb_analyst`，不要写「四、可参考案例」，不要编造品牌探店。  
引用格式、何时检索、要不要写进聊天，都以本文件为准，不要到 AGENTS 或「基本规则」里另写一套。

## 何时检索

- 画像深度足够、准备写会议材料时：调用一次 `kb_analyst`
- 用户主动问「有没有案例 / 探店笔记 / 吴探长做过类似的吗」：可以提前调用这一次（仍计入「子代理只能一次」）

## 调用方式

1. 先回复用户：告知正在查知识库，避免空等
2. `task()` → `kb_analyst`，把已收集到的城市、背景、赛道、阶段、问题、目标、计划（有则全部）传给它
3. 只用它返回的 **1–2 个品牌**；子代理分析原文不要逐字照搬

## 引用规则

- 检索命中了用户品类（标题/品牌含「火锅」等）→ **必须点名该品牌**，禁止说「库里没有该品类笔记」
- 子代理给了 **探店笔记网页 URL** → 写成 `[品牌 · 看探店笔记](完整URL)`，禁止只写品牌名、禁止编造/截短路
- 没 URL 才只写品牌；不要把知识库当目录甩出 70 条链接
- 禁止使用知识库未命中的品牌名单凑数

## 材料落点

写入会议材料 **「四、可参考案例」**（填真实品牌，不要把骨架说明留在成品里）。

交付材料时，对用户的可见回复也必须点名这 1–2 个品牌（有 URL 用 markdown 链接），不能只 save 不展示。  
用户主动要案例、而画像仍在收集时：用同样链接格式作答，然后继续只追问 1 个主问题。
