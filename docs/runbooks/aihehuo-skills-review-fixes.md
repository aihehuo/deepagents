# 技能读写分离 review 修复

日期：2026-09-14。处理两轮 review 中的问题，未提交或部署。

## 修复内容

1. 模型文件后端改为技能目录只读。通用 write/edit/upload 全部拒绝；read/grep/download 不能读取画像目录，默认 glob 也限制到技能目录。成员、管理图及继承后端的子图均无法通过通用文件工具改写画像。可信业务保存工具继续使用宿主画像存储与原有身份、执行绑定、fencing、远端确认校验。
2. 公网工具响应进入独立 `public_reads` 事实集合，按本轮模型调用 ID、工具名称和官方来源关联。第二轮修复改为保存工具可见的完整 JSON `document` 或 Markdown `text`，包括全部返回记录、嵌套字段、项目合作信息、博客正文及分页数据；证据不再独立截断数量、字段、字段长度或工具响应个数。响应大小继续由公共 HTTP 客户端的 4 MB 上限控制，请求 `per` 仍为 1–500。忽略失败、未关联及此前轮次结果；不写入候选、群成员匹配或动作凭证。公网回复不经过旧的候选虚构擦除及画像匹配模板，但继续经过能力守卫和事实校验。公网人物信息不能支持群内匹配或 @。公开查询由主图执行，通用子图只提供思路，避免查询证据丢在子图摘要里。
3. API 与 Celery worker 复用同一个四种权限图初始化函数，每个进程内共用模型和 checkpointer。缺少受限图时直接报错；同步入口在占用运行槽位前完成图选择。可信权限加入加密入队信封，worker 恢复权限并再次应用全局禁写设置，不接受请求 metadata 提权。
4. 按实际读写工具装配系统提示。只有完整 legacy 组合保留完整旧提示；其他组合保留风格和建议回复，并按可用工具添加指令。已知画像的轮次提醒按写权限装配，公网及无读权限会话不再注入旧匹配重访和搜索放宽指令。第二轮修复移除了公网读提示对“已保存”的全面禁止；画像保存权限和成功确认交给独立写能力与可信工具结果控制。

## 接口及上线兼容性

- 工厂函数的参数名、位置和默认值不变；`create_member_agent` 的模型、checkpointer、返回类型，`build_member_graphs` 的模型类型，`create_anonymous_agent` 和权限选择方法的返回注解已细化。
- 内部实验性 `PublicReadGround` 改用完整 `document`；`records` 为从 document 派生的只读属性，不再单独复制和截断人才数组。
- `known_profile_system_message` 新增可选关键字参数 `can_write_profile`，默认保持旧行为。
- 回复 finalizer、ground builder 和 grounding gate 新增可选关键字参数 `public_reads`，默认保持旧行为；内部 GroundBlock 新增默认空的同名字段。公网事实不加入 Rails 候选或 callback 协议。
- 手工构造 AppState 的调用方必须显式提供对应受限图。生产 API 与 worker 已统一初始化，相关旧测试构造已更新。
- 没有权限字段的旧队列信封按拒绝读写处理。上线前排空旧任务，再协调升级 API 与 worker，并确认模式开关、安装技能和 runtime 挂载一致。
